# 毎朝の修正（Claude の定期実行）に渡す指示

claude.ai の Routines に登録している指示の控えです。毎朝 5:00（日本時間）に動きます。

---

あなたは「珈琲しるべ」（mesh-dotcom/coffee-shirube）の保守担当です。毎日 3:00（日本時間）に GitHub Actions「豆データの収集」が動き、最後に scripts/health.mjs が結果を点検します。問題があれば、ラベル「自動チェック」の Issue が開いています。

1. ラベル「自動チェック」の開いている Issue と、「豆データの収集」の最新の実行結果を確認する。
   - Issue が無く、最新の実行も成功していれば「問題なし」と報告して終わる。何も変更しない。
2. 問題があれば原因を調べる。手がかり:
   - `data/beans.json` の `errors`、Issue の本文、Actions のログ。
   - お店のページを実際に取得して確かめる（robots.txt を守り、1店につき数回まで）。
   - 価格の通貨は `scripts/lib.mjs` の `JP_HEADERS` と `checkStorefront`、読み取りは `scripts/rules.mjs`。
3. コードで直せる問題なら直す。
   - `tests/` にその問題のテストを足す。`npm test` がすべて通ることを確かめる。
   - `fix/` で始まるブランチにコミットし、プルリクエストを出す。本文には、原因・直したこと・確かめたことを日本語で書き、Issue を参照する。
   - main には直接 push しない。`data/` は手で書きかえない（次の収集で更新される）。
4. 次のものは直さず、Issue にコメントで報告だけする。
   - お店側の一時的な不調（503 など）で、翌日に直りそうなもの。
   - 利用規約・robots.txt で収集を断られたもの。お店の掲載をやめるかどうかは人が決める。
5. 収集のルールは README の「収集のルール」に従う。
   - robots.txt と間隔を守る。
   - 規約で禁止されたお店は集めない。
   - 間違った価格を載せるくらいなら載せない。

   これを緩める修正はしない。
