# 法的な確認リスト（珈琲しるべ）

公開されている法令とガイドラインをもとに整理したものです（2026年10月13日に作成、11月12日に見直し）。弁護士の確認を経たものではありません。収益化の前など大きな節目では、専門家に相談してください。

- ✅ 対応済み（コードやサイトの表示で対応しています）
- 👤 運営者の作業（公開前に、自分で済ませてください）
- ⏸ 収益化するときの作業

## 1. 著作権（著作権法 30条の4・47条の5）

事実（産地・品種・精製・価格など）には著作権がありません。一方、商品の説明文や写真には著作権があります。

このサイトは、URLを案内する「所在検索サービス」（47条の5第1項第1号）にあたります。対象になるには、政令の基準（施行令7条の4、施行規則4条の4・4条の5）を満たす必要があります。

| 項目 | 状態 | 対応 |
|---|---|---|
| 説明文・写真を載せない | ✅ | 読み取るのは事実の項目だけです。項目ごとに文字数の上限があり、風味は16字以内の単語に限ります。句点を含む文は捨てます。写真のURLも持ちません。上限を超える値は、キャッシュに残す前に落とします。 |
| 集めたページを残さない（漏えい防止） | ✅ | ページの本文は、読み取るあいだメモリに置くだけです。`data/cache.json` には、読み取った事実だけを残します。 |
| robots.txt に従う（施行規則4条の4第1号） | ✅ | RFC 9309 に沿って読みます。`CoffeeShirubeBot` あての指定があればそれを、なければ `*` の指定を使います。robots.txt がサーバーエラーや接続できないときは、そのお店から何も取りません。見つからない（404など）ときは制限なしとみなします。`Crawl-delay` にも従い、30秒より長い指定のお店からは取得しません。Shopify のお店の robots.txt は、公開されている商品ページなどは収集してよいとしたうえで、カート・チェックアウト・アカウントのページを禁止しています。あわせて、買い物を代行するAIエージェント向けの決まり（購入には買い手の承認が要る、など）が書かれています。珈琲しるべのボットは商品情報を読むだけで、購入の操作はしません。 |
| ページの noindex に従う（同 第2号） | ✅ | `meta robots` と `X-Robots-Tag` を見ます。トップページが noindex ならそのお店ごと、商品ページが noindex ならその商品を載せません。トップページは毎回、商品ページは初めて載せるときと、その後2〜3週間ごとに確かめなおします。 |
| ID・パスワードで守られた情報を取らない | ✅ | ログインやパスワードのページへ転送されたら、そこで取得をやめます。 |
| アクセスの頻度を抑える | ✅ | 収集は1日1回（3:00）です。同じお店へは3秒以上あけてアクセスします。429やサーバーエラーが返ったら、そのお店はその日の収集を打ち切ります。岡崎市立中央図書館事件を踏まえ、相手のサーバーに負担をかけない作りにしています。 |
| 利用規約で禁止しているお店を除く | ✅ | 新しいお店は、収集の前に規約を自動で判定します。自動収集の禁止があれば `ng`、判断がつかなければ `review` として、どちらも集めません。規約の確認が済んでいないお店も集めません。 |
| 規約があとから変わったときに気づく | ✅ | 集めているお店の規約ページを30日ごとに読みなおします。自動収集を禁止する書き方が加わっていたら、そのお店の収集を止めて、実行結果に知らせを出します（許諾をもらったお店は知らせるだけ）。 |
| 規約を目で確かめる | 👤 | 自動の判定は目安です（API なしではキーワードで、キーがあれば Claude が判定）。各店の規約ページを自分で読み、Actions の「お店の管理」→「規約を確認した（掲載してよい）」で記録してください。記録がまだのお店は、毎回の実行結果の「確認のお願い」に規約のURLつきで出ます。いまの3店は Claude が規約ページを読んで記録したものです。 |
| 連絡先の表示（施行規則4条の5第2号） | ✅ | サイトのフッター「お問い合わせ・掲載の停止」に表示します。収集ボットの名乗り（User-Agent）にも同じ連絡先を入れます。既定は GitHub の Issues です。 |
| 連絡しやすい窓口にする | 👤 | GitHub のアカウントがないお店もあります。できれば専用のメールアドレスかフォームを用意して、リポジトリの変数 `CONTACT_URL` に入れてください。 |
| 事前の取組（施行規則4条の5第1号） | 👤 | 施行規則は「要件の解釈を記載した書類の閲覧、学識経験者に対する相談その他の必要な取組」をあらかじめ行うよう求めています。公開前に文化庁の「基本的な考え方」を読み、下の表に日付を記録してください。 |

## 2. 景品表示法（ステルスマーケティング規制、2023年10月1日から）

| 項目 | 状態 | 対応 |
|---|---|---|
| 広告・アフィリエイト | ✅ | いまはありません。フッターの「掲載のルール」にもそう書いています。 |
| PR の表示 | ✅ | `data/shops.json` のお店（または豆）に `"ad": "paid"`（有料掲載）か `"ad": "affiliate"`（アフィリエイト）を付けると、次の3か所に表示が出ます。カードの右上とお店の見出しに「PR」、結果のすぐ上に「PRは広告・アフィリエイトを含む掲載です」という説明です。 |
| おすすめ順の決め方 | ✅ | フッターの「掲載のルール」に、情報のそろい具合と新着で並べていることを書いています。掲載料やアフィリエイトでは順番を変えません。コード上も、並び順の点数（`_score`）に広告の有無は入っていません。 |
| 有料で上に出す枠を作るとき | ⏸ | その枠を「PR」や「広告」として、ほかの結果と分けて表示してください。フッターのおすすめ順の説明も書き換えます。 |

## 3. 価格・在庫の正確さ

| 項目 | 状態 | 対応 |
|---|---|---|
| 取得日時と注意書き | ✅ | 結果のすぐ上に「価格・在庫は◯月◯日 ◯:◯◯時点の情報です。最新の情報は各販売店でご確認ください。」と出します。 |
| 古い情報 | ✅ | 豆ごとに、確かめた日（`checkedAt`）を残します。その日に確かめられなかった豆は、カードに確かめた日を出します。7日を過ぎた豆は載せません。 |
| 見本データ | ✅ | 公開用の `index.html` は見本データを使いません（`USE_SAMPLE = false`）。`data/beans.json` が読めないときは「準備中」と出し、古い価格を今の情報のように見せません。 |
| 売り切れ | ✅ | 在庫のない商品は載せません。 |

## 4. 電気通信事業法（外部送信規律、2023年6月16日から）

| 項目 | 状態 | 対応 |
|---|---|---|
| 外部送信の公表 | ✅ | 外部へ送っているのは Google Fonts だけです。フッターの「外部送信について」に、送られる情報（IPアドレス、ブラウザやOSの情報）、送り先（Google LLC）、目的を書いています。フォントの読み込みはリファラーを送らない設定です。 |
| アクセス解析・広告タグ | ✅ | 使っていません。「気になる」は端末の中（ブラウザの localStorage）にだけ保存し、どこにも送りません。 |
| 届出 | ✅ | 届出が必要になるのは、総務大臣が指定する大規模な検索サービスやSNS（利用者が1,000万人規模）です。このサイトの規模では要りません。 |
| 解析や広告のタグを入れるとき | ⏸ | 送り先・送られる情報・目的を、フッターの「外部送信について」に書き足してください。 |

## 収益化する前にやること

1. `data/shops.json` の `"commercial"` を `true` にします。情報の商業利用を規約で禁止しているお店は、自動で対象から外れます。いまは LIGHT UP COFFEE が該当します（規約 第6条5号）。
2. 続けて載せたいお店には許諾をもらい、Actions の「お店の管理」→「掲載の許諾をもらった」で記録します（メモに、日付と許諾の方法を書いておきます）。
3. 有料掲載やアフィリエイトのお店に `"ad"` を付けます。サイトに「PR」が出ることを確かめてください。
4. 広告やアフィリエイトのタグを入れるなら、「外部送信について」に書き足します。
5. 使うアフィリエイトサービス（ASP）の規約で、リンクの貼り方や表示のルールを確かめます。
